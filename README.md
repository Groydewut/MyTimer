# Go Timer

Настольный таймер обратного отсчёта с русскоязычным интерфейсом. Приложение построено на [Wails](https://wails.io/): пользовательский интерфейс работает на Svelte и Vite, а состояние и отсчёт времени реализованы на Go.

## Возможности

- Установка продолжительности в часах, минутах и секундах.
- Быстрый выбор интервалов на 5, 10 и 25 минут (Pomodoro).
- Запуск, пауза, продолжение с оставшегося времени и сброс.
- Отображение времени в формате `ММ:СС`, а при длительности от часа — `ЧЧ:ММ:СС`.
- Звуковой сигнал при окончании отсчёта и системное уведомление, если браузерная среда поддерживает уведомления и приложению разрешено их показывать.
- Сохранение последней выбранной продолжительности в `localStorage`; при следующем запуске она восстанавливается в форме ввода.
- Светлая и тёмная темы в соответствии с настройкой операционной системы.

## Использование

1. При запуске задайте время или выберите один из пресетов.
2. Нажмите **«Подтвердить»**, чтобы перейти к экрану таймера.
3. Нажмите **«Старт»** для начала отсчёта.
4. Во время отсчёта можно нажать **«Пауза»**, а затем **«Продолжить»**.
5. Нажмите **«Сброс»**, чтобы остановить текущий таймер и вернуться к установке времени.

Продолжительность должна быть больше нуля. Настройки последней продолжительности сохраняются в браузерном хранилище приложения. Текущее состояние отсчёта (например, запущен ли таймер и сколько времени осталось) сохраняется только в памяти работающего приложения.

## Технологии

- **Go** — логика таймера и Wails backend.
- **Wails v2** — оболочка настольного приложения и связь между Go и frontend.
- **Svelte 3** — пользовательский интерфейс.
- **Vite 3** — сборка frontend и dev-сервер.

Go-модуль проекта — `github.com/Groydewut/go-timer`; версии Go и Wails указаны в `go.mod` (`go 1.27.1`, Wails `v2.17.0`). Список frontend-зависимостей и команды npm находятся в `frontend/package.json`; настройки команд Wails — в `wails.json`.

## Требования

- Go версии 1.27.1 или совместимой с директивой `go` в `go.mod`.
- Wails CLI версии 2.17.0.
- Node.js и npm — для установки frontend-зависимостей и сборки интерфейса.
- Системные зависимости Wails для целевой ОС:
    - **Windows:** WebView2 Runtime.
    - **macOS:** инструменты командной строки Xcode.
    - **Linux:** GTK и WebKit2GTK dev-пакеты; точные названия зависят от дистрибутива.

Актуальные требования и инструкции по установке Wails опубликованы в [официальной документации](https://wails.io/docs/gettingstarted/installation/).

## Разработка

Откройте терминал в корне проекта. После установки системных зависимостей и Wails CLI запустите приложение в режиме разработки:

```sh
wails doctor
wails dev
```

`wails dev` запускает desktop-приложение и frontend dev-сервер с горячей перезагрузкой. Для типовой конфигурации Wails также предоставляет dev-сервер по адресу `http://localhost:34115`; его можно открыть в браузере для отладки.

Если нужно установить frontend-зависимости или собрать интерфейс отдельно:

```sh
npm install --prefix frontend
npm run build --prefix frontend
```

Frontend вызывает Go-методы через Wails bindings, поэтому запуск одного только Vite dev-сервера не заменяет запуск приложения через `wails dev`.

## Сборка приложения

Из корня проекта выполните:

```sh
wails build
```

Команды установки и сборки frontend задаются в `wails.json`; Wails использует их при сборке приложения. Результат зависит от ОС и настроек сборки и обычно размещается в `build/bin/`. Для получения приложения под другую платформу сборку следует выполнять согласно требованиям Wails для этой платформы.

## Как устроен таймер

- `Timer` в `timer.go` хранит длительность, оставшееся время и состояние `Stopped`, `Running` или `Finished`. Отсчёт выполняется с интервалом в одну секунду.
- `App` в `app.go` предоставляет frontend-методы `Start`, `Stop`, `Resume`, `Reset`, `SetDuration`, `GetLeft` и `GetStatus`.
- Backend отправляет Wails-событие `tick` с оставшимся количеством секунд и событие `finished` при завершении.
- `frontend/src/App.svelte` подписывается на эти события, обновляет интерфейс и обрабатывает звук и системное уведомление.

## Установка и сборка в Arch Linux

Команды ниже выполняются из корня репозитория на актуальной системе Arch Linux.

### 1. Установить инструменты и системные библиотеки

```sh
sudo pacman -Syu
sudo pacman -S --needed base-devel go npm gtk3 webkit2gtk-4.1
```

Arch Linux предоставляет WebKitGTK 4.1, а Wails по умолчанию ищет версию 4.0. Поэтому для сборки в Arch необходимо передавать Go build tag `webkit2_41` (см. шаг 4). После установки проверьте системные зависимости командой `wails doctor`.

### 2. Установить Wails CLI

В `go.mod` уже настроен module path `github.com/Groydewut/go-timer` и зависимость Wails `v2.17.0`. Установите Wails CLI той же версии:

```sh
go install github.com/wailsapp/wails/v2/cmd/wails@v2.17.0
export PATH="$(go env GOPATH)/bin:$PATH"
wails version
wails doctor
```

Команда `export` действует в текущем терминале; для последующих сеансов добавьте `$(go env GOPATH)/bin` в `PATH` своей оболочки.

### 3. Установить frontend-зависимости и собрать интерфейс

Установите зависимости, затем соберите интерфейс:

```sh
npm install --prefix frontend
npm run build --prefix frontend
```

Если `frontend/node_modules` перенесён с другой ОС и сборка сообщает о несовместимом esbuild, удалите этот каталог и повторите установку на Arch:

```sh
rm -rf frontend/node_modules
npm install --prefix frontend
npm run build --prefix frontend
```

Не добавляйте `node_modules` в Git.

### 4. Проверить и собрать приложение

```sh
go test ./...
wails build -tags webkit2_41
```

`wails build` запускает frontend-сборку, заданную в `wails.json`, и затем собирает Go-приложение. Для разработки в Arch Linux используйте `wails dev -tags webkit2_41`. При необходимости frontend можно предварительно собрать отдельно командой из шага 3.

Для разработки с горячей перезагрузкой запустите:

```sh
wails dev
```

Собранное приложение обычно появляется в `build/bin/`. Если сообщение об ошибке содержит `webkit2gtk-4.0 was not found`, проверьте, что сборка запущена с `-tags webkit2_41`. Ошибки других GTK/WebKitGTK-зависимостей проверьте через установленные пакеты и `wails doctor`; ошибки `esbuild`/Vite — по шагу 3; ошибки Go-модуля или импорта — через `go.mod`, `go.sum` и `go mod tidy`.

Сейчас в проекте нет отдельных Go-тестов; `go test ./...` проверяет, что backend компилируется.
